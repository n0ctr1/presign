WHAT A VERDICT ACTUALLY COSTS

Rules read the transaction's effects, not its calldata.

Calldata says what a transaction claims to do. The state diff says what it does, and the two part company exactly where it matters — a router, a multicall, or a permit forwarding an approval on somebody's behalf.

i

Simulate

The unsigned transaction runs against a fork pinned near chain head. Reverts are detected by a separate call, never inferred from an empty diff.

FORK RE-TAKEN EVERY 5 MIN

ii

Read state

R1 recovers the allowance slot from the diff and proves an approval that hands over the balance. R2 reads proxy slots directly, because admin getters revert for everyone but the admin.

RPC ONLY · NO INDEXER

iii

Ask the layer

R3 checks protocol accounting against deployments that index this counterparty and sit inside a freshness budget. R4 asks whether anyone has ever indexed it at all.

FRESHNESS-GATED · 30 S BUDGET

iv

Tier

A definite finding outranks uncertainty. The absence of findings does not — a rule that could not run turns an otherwise clean result into unavailable.

FOUR OUTCOMES, NO FIFTH

THE FOURTH OUTCOME IS THE POINT

"Nothing found" and "could not look" are different answers.

Collapse them and a green verdict becomes reachable on data nobody ever saw. unavailable is a tier in the type system, not an error code, so a rule that fails cannot be mistaken for a rule that found nothing.

LOW

Every rule ran and none found anything, against sources named in the response with the lag each one carried.

  • signs without confirmation
  • source and lag reported
  • journalled to Hedera

MEDIUM

Real but standing — an upgradeable proxy, a bounded approval. True of most of DeFi, so it asks a human rather than refusing.

  • escalates to a Ledger
  • device shows the decoded intent
  • only a refusal counts as one

HIGH

An implementation swap inside the judged transaction, protocol accounting that cannot add up, or a counterparty deployed hours ago that nobody has indexed.

  • never reaches the device
  • a prompt is a request, and people approve prompts
  • reason returned to the agent

UNAVAILABLE

Fresh context could not be obtained. Not a softer low: the honest answer is that this transaction was not evaluated.

  • every rule that failed is named
  • with the reason it failed
  • no payment is taken

THE FIELD THE INCUMBENTS DO NOT RETURN

Provenance, down to the lag.

A verdict a caller cannot check is a number they have to trust, and unverifiable risk scores are what the incumbents already sell. Every answer names the deployment that produced it and how far behind chain head that deployment was.

Aged, not trusted
Effective lag is the measured lag plus the age of the measurement, so a warm cache cannot turn stale data green.
Independent head
Chain head comes from an RPC, never the indexer. One source for both would read a stalled indexer as a healthy one.
Pinned, not floating
Queries address an immutable deployment id. A subgraph id drifts to whatever its owner publishes next.
Never ordered by score
The registry's reliability score tracks traction, and therefore age. Sorting by it would reintroduce the bias the layer removes.

MEASURED, NOT ESTIMATED · npm run coverage

NO KEY, NO ACCOUNT, NO SUBSCRIPTION

Ask the price first, then decide to pay.
